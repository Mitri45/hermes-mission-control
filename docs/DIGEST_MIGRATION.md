# Daily Digest Migration Guide (DIM-232)

## Overview

This document describes the migration path from Telegram-only digest delivery to the new Hermes Web View Daily Digest screen.

## Current State (Pre-Migration)

- Digest content generated by cron jobs (arXiv, web, custom sources)
- Delivered exclusively via Telegram
- No persistent storage or browsing capability

## Target State (Post-Migration)

- Digest content available in Hermes Web View as first-class screen
- Persistent storage with daily grouping and timestamps
- Source attribution and metadata visibility
- Dual-instance aware (PC/Pi)
- Replication lag visibility for ops/debugging

## Migration Strategy

### Phase 1: Parallel Delivery (Current)

During the transition period, both delivery paths are active:

1. **Primary**: Web View digest screen (`/dashboard/digest`)
   - Full-featured browsing with daily grouping
   - Instance and source filtering
   - Freshness indicators and replication metadata

2. **Fallback**: Telegram delivery (temporary)
   - Continues to work as before
   - Provides redundancy during adoption

### Phase 2: Web-View Only (Future)

Once Web View adoption stabilizes:

1. Telegram delivery becomes opt-in via settings
2. Digest ingestion continues via cron jobs (unchanged)
3. All browsing happens through Web View

## Implementation Details

### Backend API

**Base Path**: `/api/digest`

#### Endpoints

| Method | Path | Description |
|--------|------|-------------|
| GET | `/api/digest` | List digests with filtering and pagination |
| GET | `/api/digest/stats` | Get digest statistics |
| GET | `/api/digest/{id}` | Get single digest entry |
| POST | `/api/digest` | Create digest entry (admin/testing) |

#### Query Parameters (List)

- `instance`: Filter by source instance (`all` | `pc` | `pi`)
- `source`: Filter by source type (`arxiv` | `web` | `custom` | `telegram`)
- `page`: Page number (default: 1)
- `page_size`: Items per page (default: 50, max: 250)
- `days`: Filter to last N days (optional)

#### Response Format

```typescript
interface DigestEntry {
  id: string
  title: string
  summary: string
  source: 'arxiv' | 'web' | 'custom' | 'telegram'
  source_url?: string
  source_instance: 'pc' | 'pi'
  tags: string[]
  ingested_at: string  // ISO timestamp
  updated_at: string   // ISO timestamp
  replicated_at?: string  // ISO timestamp, null if not replicated
  replication_seq?: number  // Sequence number for sync
  metadata: Record<string, unknown>
}

interface DigestListResponse {
  entries: DigestEntry[]
  groups: DigestDayGroup[]  // Grouped by date for UI
  total: number
  page: number
  page_size: number
  has_more: boolean
}

interface DigestStatsResponse {
  total_entries: number
  by_source: Record<string, number>
  by_instance: Record<string, number>
  last_24h: number
  last_7d: number
  replication_lag_seconds?: number
}
```

### Frontend Implementation

**Route**: `/dashboard/digest`

**Stack**:
- TanStack Router for routing
- TanStack Query for data fetching and caching
- TanStack Table (where applicable)

**Features**:
- Daily grouping with "Today" / "Yesterday" / date headers
- Instance filter tabs (All / PC / Pi)
- Source filter buttons (All / arXiv / Web / Custom / Telegram)
- Freshness indicators (green < 1h, yellow < 24h, red > 24h)
- Replication status badges
- Detail modal with full content and metadata

### Data Storage

**Location**: `~/.hermes/mission-control/digests/entries.jsonl`

- Append-only JSONL format
- Simple file-based storage (production: migrate to database)
- Supports dual-instance replication markers

### Cron Job Integration

Cron jobs should be updated to POST new entries to the digest API:

```python
import requests

# After generating digest content
response = requests.post(
    'http://localhost:8000/api/digest',
    json={
        'title': 'Paper Title or Content Headline',
        'summary': 'Generated summary...',
        'source': 'arxiv',  # or 'web', 'custom', 'telegram'
        'source_url': 'https://arxiv.org/abs/...',
        'source_instance': 'pc',  # or 'pi'
        'tags': ['ml', 'nlp'],
        'metadata': {'arxiv_id': '...', 'categories': [...]}
    }
)
```

## Fallback Path Documentation

### Telegram Continuity

During the migration window, Telegram delivery continues to work:

1. **Existing cron jobs**: No changes required - continue sending to Telegram
2. **New digest entries**: Optionally POST to `/api/digest` after Telegram send
3. **Migration completion**: Once confirmed, Telegram becomes optional

### Testing the Web View

```bash
# Start the Mission Control API
./start.py

open http://localhost:8000/dashboard/digest

open http://localhost:8000/dashboard/digest
```

### Verifying Dual-Instance Sync

1. Create entry on PC instance
2. Check Pi instance digest list
3. Verify replication metadata (`replicated_at`, `replication_seq`)
4. Monitor replication lag in stats panel

## Troubleshooting

### No digests appearing

1. Check storage path exists: `ls ~/.hermes/mission-control/digests/`
2. Verify API is running: `curl http://localhost:8000/api/digest/stats`
3. Check cron jobs are POSTing to API

### High replication lag

1. Check network connectivity between PC/Pi
2. Verify memory replication is working
3. Review ingest metrics: `GET /api/memory/ingest/metrics`

### Missing source filters

Available sources: `arxiv`, `web`, `custom`, `telegram`
Add new sources by updating the `DigestSource` type in both frontend and backend.
